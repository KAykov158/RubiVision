# Canonical domain and database contract

Retain source concepts: PuzzleType = 222|333|444|555|666|777; Penalty = NONE|PLUS_TWO|DNF; TimingSource = KEYBOARD|TOUCH|SMART_CUBE; ActivityLabel = MOVEMENT|PAUSE|UNCERTAIN. IDs are UUID; UTC timestamps ISO 8601; durations finite nonnegative integer milliseconds. Solve has id, sessionId, scrambleId, puzzle, rawTimeMs, penalty, startedAt, completedAt, timingSource, notes?. Scramble has id, puzzle, notation, generatorVersion, createdAt. Session has id, name, puzzle, createdAt, updatedAt. Recording has id, solveId, createdAt, durationMs, mimeType, optional dimensions, storage key only if uploaded, timerStartOffsetMs. Analysis has id, solveId, recordingId, modelVersion, featureSchemaVersion, createdAt, segments, qualityWarnings.

Effective time is DERIVED: DNF => null; PLUS_TWO => rawTimeMs + 2000; NONE => rawTimeMs. Do not persist a separately editable final time. All segments and feature windows are half-open [startMs,endMs) in recording time, 0 <= start < end <= duration, with non-overlapping final segments and confidence null or in [0,1].

Recommended database tables: sessions(user_id,id,puzzle,...), scrambles(user_id,id,puzzle,notation,generator_version,...), solves(user_id,id,session_id,scramble_id,puzzle,raw_time_ms,penalty,...), settings(user_id primary key,settings_json,version,...), recordings(user_id,id,solve_id,uploaded_storage_path nullable,...), analyses(user_id,id,solve_id,recording_id,model_version,feature_schema_version,segments_json,...). Enforce user-consistent composite foreign keys or validated database triggers; RLS alone is not sufficient for cross-owner references. Use unique(user_id,id) as needed for composite FK targets. Use CHECK constraints for duration, enums, time ordering, and JSON payload versions. Storage keys cannot point to other users' uploads.

Typed repositories: SessionRepository CRUD/list; ScrambleRepository create/get; SolveRepository save/get/list/updatePenalty/updateNotes/delete; SettingsRepository read/upsert; RecordingRepository metadata CRUD/upload opt-in; AnalysisRepository create/list/get. UI consumes services and typed result/errors, not raw SQL. Generate Supabase DB types from migrations; never trust compile-time typing without runtime validation.

Model manifest MUST define feature names/order, preprocessing, missing values, label IDs, frame/window sampling, model version, thresholds, and checksums. Browser inference must validate manifest compatibility before running.
