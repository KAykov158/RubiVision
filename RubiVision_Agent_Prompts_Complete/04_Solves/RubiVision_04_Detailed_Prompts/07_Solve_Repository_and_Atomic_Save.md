## Objective and exact implementation scope
Implement repository `save/get/list` and solve service to persist a completed solve exactly once. Use a stable solve ID/idempotency key generated for the completion event; repeated callbacks, double clicks and retries with the same ID must not insert duplicates. Transactionally validate existing session and scramble and save any required new immutable scramble together with solve, so failures do not leave a partial solve. Reject same ID with conflicting payload; identical retry should be a no-op or return existing record. Explicitly handle interrupted transactions and app reload; never create a second solve from a retry. Respect timer startedAt/completedAt and timingSource, with no fake timestamps.
