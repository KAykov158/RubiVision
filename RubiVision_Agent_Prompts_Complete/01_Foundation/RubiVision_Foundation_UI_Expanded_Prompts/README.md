# Foundation/UI — Agent Prompt Index

Run prompts sequentially, skipping only tasks already demonstrably implemented. Every agent must inspect the repository first and read the shared 00_* contracts. Do not start the next prompt until the current prompt is verified or its blocker is documented.

01. [Repository audit and architectural decisions](01_Repository_Audit.md) — Inspect package.json, source tree, scripts, tests, current routing, styling, providers and dependencies. Create an inventory of existing working behavior and gaps. Decide whether to retain current router, styling framework and test stack. Record decisions without rewriting code.
02. [Application bootstrap and strict TypeScript](02_Application_Bootstrap.md) — Ensure one working React application entry, App root and providers composition. Configure strict TypeScript, Vite/build and scripts using existing project conventions. Do not replace installed tools without justification.
03. [Design tokens and visual language](03_Design_System.md) — Define consistent semantic colors, spacing, typography, radii, elevations, focus rings and breakpoints. Prioritize legibility of scramble and timer values. Use CSS variables or the existing styling system.
04. [Desktop and mobile application shell](04_Application_Layout.md) — Implement persistent AppLayout containing main content, header and navigation. Use desktop sidebar and compact mobile navigation; avoid overlays covering content. Make scrolling behavior explicit.
05. [Routes and navigation semantics](05_Routing.md) — Configure routes for /timer, /history, /statistics, /analysis and /settings, with / redirect and a 404 page. Preserve browser history and deep links. Prefer existing routing package.
06. [Reusable UI primitives](06_Shared_Components.md) — Build a small accessible set of Button, IconButton, Card, Dialog, Select, Input, EmptyState, StatusMessage and LoadingIndicator. Avoid building a large generic UI library.
07. [Timer page visual structure](07_Timer_Page_UI.md) — Build the presentation-only timer page with puzzle/session selector slots, scramble panel, primary time display, state/status text and secondary action areas. Do not implement timing calculations or generate fake scrambles.
08. [Solve history presentation](08_History_Page_UI.md) — Implement history page skeleton with session/puzzle/date filter controls, sortable list/table, responsive row layout, solve detail panel and empty/error states. No IndexedDB calls in components.
09. [Statistics presentation](09_Statistics_Page_UI.md) — Build statistics page layout for best, mean, averages, trends and chart regions using typed optional data. Actual statistical calculations belong to module 05.
10. [Video analysis presentation](10_Analysis_Page_UI.md) — Build analysis page shell for selecting a solve, showing recording/video, analysis status, timeline slot, movement/pause/uncertain legend and warnings. No ML inference here.
11. [Settings page presentation](11_Settings_Page_UI.md) — Create organized settings groups for appearance, timer/inspection, puzzle defaults, camera/privacy, data management and analysis options. Keep controls disabled or explanatory when underlying services are absent.
12. [Theme switching and adaptive behavior](12_Themes_Responsive.md) — Implement dark/light/system theme selection through a provider; use system preference on initial load if no saved preference. Define persistence adapter, SSR-safe initialization where relevant, and avoid flashing incorrect theme where possible.
13. [Accessibility and keyboard behavior](13_Accessibility.md) — Audit landmarks, heading order, focus visibility, route-change focus, link labels, dialog traps, error announcements and color contrast. Prevent global timer keyboard shortcuts from hijacking text fields.
14. [Application providers and integration contracts](14_State_Integration.md) — Establish typed service injection and stable state ownership boundaries. UI should consume timer/scramble/solve/analysis services, not import persistence internals. Keep running timer state above route pages or in stable external store.
15. [Loading, empty, error and recovery UX](15_Error_Recovery.md) — Add app-level error boundary and page-level error displays, retry affordances and consistent async loading. Keep failures isolated so camera or analysis errors do not disable timing/history.
16. [Foundation quality gate and handoff](16_Foundation_QA.md) — Run available unit, integration, accessibility and browser tests. Add navigation, responsive, theme, error-boundary and state-preservation tests. Document implementation evidence and next-module interfaces.

These prompts expand `01_Foundation_UI.md` only. They do not replace the Timer, Scramble, Storage, Statistics, Camera or ML module prompts.
